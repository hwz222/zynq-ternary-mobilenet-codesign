twn_fuse 暫存器手冊

PL 加速器 twn_fuse 的每個暫存器：每一段位元代表什麼、PS（driver 與 app）和 PL（硬體）各自怎麼使用它，以及一次執行從開機到每一幀依序寫了哪些值。

先看這裡

  • PS 指 Zynq UltraScale+ 的 ARM 處理器，上面跑 Linux、twn_fuse driver 與 app；PL 指 FPGA 邏輯，暫存器實體在 rtl/fuse/twn_csr.v。
  • 暫存器窗口在 0xA000_0000 開始的 64 KB，PS 經 M_AXI_HPM0_FPD 用 AXI4-Lite 存取。本頁的位址都是 offset，實際位址 = 0xA000_0000 + offset。0xA001_0000 的 obs_gpio 是另一個 IP，不在本頁。
  • app 不直接碰暫存器：v1.1 的 mmap 只給 DMA buffer，正常執行時暫存器由 driver 透過 ioctl 代為讀寫；除錯用的 NBLK 寫入與 PIX_NZ、CAP 讀取走 debugfs。本頁「對 PS 的意義」列出 driver 在哪一行讀寫、為什麼，以及 app 透過哪個 ioctl 觸發。
  • 匯流排規則（twn_csr.v:6-10）：每次寫入都是整個 32 位元字，wstrb 被忽略；沒有定義的位址（例如 0x0004、0x0068–0x00FC、0x010C、0x0140–0x03FC、0x0800–0x0FFC、0x1800 以後）讀出 0、寫入被忽略；每次回應都是 OKAY，所以寫錯位址不會有 bus error。
  • 位元圖由左到右是 bit 31 到 bit 0，顏色代表這段位元的用法：
設定：PS 寫入，PL 持續使用；讀回的是寫入的值
狀態：PL 更新，PS 讀取；寫入忽略
命令：PS 寫入時觸發一個動作；讀出為 0
讀寫不同：讀出是狀態，寫入是命令
保留：讀出 0，寫入忽略

本頁引用的行號（driver、RTL、app、建置腳本、紀錄檔）都對應本頁所在的 commit。twn_fuse.c 在 tag v1.1.0 之後只在第 668 行以後加了註解，本頁引用的 driver 行號都在第 662 行以前，所以和板上跑的 v1.1.0 driver 相同。位址值以發佈映像那次開機的 buffer 起點 0xff_ff80_0000 計算（H10_driver_state.log 第 24 行）。

對 PL 的意義

  • 寫入 START 時，只有 block table 已檢查而且合格（STATUS[1:0] = 11）才會接受（twn_csr.v:375）；否則 START 被靜靜忽略，不會回報錯誤。
  • START 是準位不是脈衝：寫入後保持 1，frame sequencer 開始忙的那個 cycle 自動清回 0。backbone 正在忙時寫入的 START 不會排隊，也不會開始新的一幀（twn_csr.v:12-14、twn_frameseq.v:73）；但它仍讓 ap_start 高一個 cycle，而下一項的清零沒有看 busy，所以一幀跑到一半寫 START 會把 cycle 計數器和 PIX_NZ、CAP 清掉。driver 一律先等閒置才寫 START，不會發生這種情況。
  • ap_start 為 1 的那段時間，同時清零 6 個 cycle 計數器（twn_fuse_top.v:262-263）與 PIX_NZ、CAP（twn_fuse_top.v:592、610）；backbone 閒置時還會取樣 BB2HD[0]，決定這一幀要不要直送 head（twn_fuse_top.v:680）。
  • 第 NBLK−1 個 block 跑完時 done 設為 1 並保持；IRQ[0] 打開時，中斷線在下一個 cycle 拉高（中斷經過一級暫存器，twn_csr.v:329-335）。寫入 bit 1 清除 done，中斷線在下一個 cycle 落下。

對 PS 的意義

  • twn_bb_run()（TWN_IOC_BB_RUN）：twn_fuse.c:222 讀 bit 1 等到 0，因為忙碌中的 START 會被丟掉；twn_fuse.c:225 寫 0x2，清掉上一幀留下的 done，否則下一步的等待會立刻結束；twn_fuse.c:233 寫 0x1 啟動；twn_fuse.c:235 等 done（有中斷時睡在 completion 上，沒有中斷時每 50 µs 讀一次 bit 2）；twn_fuse.c:241 再寫 0x2。
  • twn_isr()：twn_fuse.c:478-479 讀 bit 2，為 1 就寫 0x2 清除，並叫醒睡在 BB_RUN 裡的 thread。
  • debugfs 的 dma_fault（twn_fuse.c:536-544）用同樣的步驟跑一幀。
  • TWN_IOC_STATUS（twn_fuse.c:154）讀出原始值；一幀逾時時 twn_fuse.c:238 把它印進 dmesg。
  • driver 只寫 0x1 與 0x2 兩種值，bit 2（irq_en）永遠是 0。

對 PL 的意義

  • bit 0、1、10:7、15:11 由 block table 的檢查（twn_desctab.v）更新：寫 CHECK 時 bit 1 先清成 0，檢查走完再設回 1；遇到第一個不合格的 block 就停，記下錯誤碼與 block 編號。
  • bit 6:2 是 frame sequencer 目前的 block 編號（twn_frameseq.v 的 blk）。
  • bit 16 在下列任一情況設為 1：列緩衝區滿了仍被寫入、residual 緩衝區已不再保有要讀的那一列、陣列仲裁拒絕一次寫入（twn_fuse_top.v:757-772）。它只記錄、不停機；只有 reset 會清，讀取不會清（twn_csr.v:322）。

對 PS 的意義

  • twn_set_table()：twn_fuse.c:185 每 10 µs 讀一次，等 bit 1 變成 1，最多 100 ms；twn_fuse.c:188-190 看 bit 0，不合格就在 dmesg 印出 bit 10:7 與 15:11，回傳 -EINVAL。
  • debugfs 的 dma_fault（twn_fuse.c:533）要求 bit 0 = 1 才執行。
  • 逾時訊息（twn_fuse.c:238）、TWN_IOC_STATUS（twn_fuse.c:155）、sysfs 的 status 檔都讀它。

driver 第 42 行的註解只列了 bit 0、1、10:7、15:11，漏了 6:2 與 16；以 RTL（twn_csr.v:498-502）為準。

bit 16 在發佈的 bitstream 正常執行時就會設起來，輸出仍然逐位元正確；講義第 8 章有說明。

3. 量測前的循序對照

進入流水線迴圈之前，mbv2_fuse_pipe.c:263-272 用 mbv2_fuse_infer() 把每張 fixture 依序跑 2 次，當作正確性的對照。每次先 mbv2_fuse_frame_pl(-1)：寫 BB2HD = 0xB、跑 BB_RUN；再 mbv2_fuse_head_run(0)：HD_START、HD_WAIT，接著用 TWN_IOC_STATUS 讀 BB2HD 核對。暫存器存取和下一節相同，只是 backbone 與 head 不重疊。

4. 每一幀

主 thread 的第 k 圈（k ≥ 1）。這一圈同時讓 backbone 跑第 k 幀、head 跑第 k−1 幀。

#ioctl 或動作暫存器讀／寫值PL 的反應
1app 直接寫 buffer——offset 0x180000第 k 幀影像（192 KB）放好
2TWN_IOC_HD_STARTHD_CTRL讀bit 1 必須是 0—

7OUT_LO ／ OUT_HI寫0xffc40000 ／ 0xff—
8CTRL寫0x1清零 cycle 計數器，取樣 BB2HD[0] = 1，跑 block 0–16；block 16 寫到 OUT + parity × 64 KB；完成時 done = 1、parity 翻轉、中斷線拉高

第 0 圈沒有上一幀可以給 head：app 先寫 BB2HD = 0xB 重設，再只跑 BB_RUN。迴圈結束後再補跑最後一幀的 head（HD_START、HD_WAIT）。從第 1 圈起不再寫 BB2HD，因為 app 記得它已經開著，值沒變就不發 ioctl（pl_hal_fuse_drv.c:215-220）。

中斷進來時（twn_isr()，twn_fuse.c:473-497）

  1. 讀 CTRL；bit 2 = 1 時寫 0x2 清除，叫醒等 backbone 的 BB_RUN。
  2. 讀 HD_CTRL；bit 2 = 1 時寫 0x4 清除，記下 head 完成，讓 HD_WAIT 可以返回。
  3. 只要處理了任何一個，就把 irq_count 加 1，再讀一次 IRQ，確保清除的寫入已經到達 PL、中斷線已經落下。

兩個引擎共用一根中斷線，所以 ISR 每次都兩個都查。沒有中斷時（use_irq=0），probe 不會打開 IRQ，driver 改成每 50 µs 讀 CTRL 或 HD_CTRL 的 bit 2。

5. 卸載（rmmod）

twn_remove() 先移除 /dev/twn_fuse 與 debugfs，再寫 IRQ = 0（twn_fuse.c:662）關掉中斷來源；接著 kernel 依相反順序釋放中斷、buffer、暫存器映射。

6. 只在觀察或除錯時

  • sysfs：讀 cycles_*（CYCLES ～ CYC_POST）、status（STATUS）、nblk（NBLK），只讀。
  • debugfs 的 regs：讀 CTRL、NBLK、STATUS、PIX_NZ、CAP0–3、BB2HD、IRQ、HD_CTRL、HD_COMMIT、HD_RQ_STAT。
  • debugfs 的 nblk：拿 bb_lock，寫 NBLK = 1–17。
  • debugfs 的 dma_fault：要求 STATUS bit 0 = 1；等 CTRL 閒置，寫 CTRL = 0x2、IN = buffer 之後第一個 byte、OUT = buffer 起點、CTRL = 0x1；等完成，寫 CTRL = 0x2，把 STATUS 印進 dmesg。
