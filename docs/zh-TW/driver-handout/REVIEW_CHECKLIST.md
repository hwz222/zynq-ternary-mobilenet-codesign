# 審稿清單

審稿人以「母語是台灣華語、英文是第二語言、會寫 C 與 RTL、但沒寫過 Linux driver 的工程師」的角度閱讀。
每一項回答「通過／不通過」，不通過要寫出具體位置與建議改法。

## A. 讀得懂

- [ ] 每一節開頭的「一句話」讀完，就知道這節在講什麼。
- [ ] 每一段先講結論，再講理由；沒有超過三行還看不出重點的段落。
- [ ] 每個英文技術名詞第一次出現時，有一句中文解釋，並收在附錄 A。
- [ ] 沒有未解釋的代號、縮寫或內部名稱。
- [ ] 一節在 10 分鐘內讀得完。

## B. 三段式完整

- [ ] 「原本怎麼做」引用了 v1.0.0 的實際程式碼，並指出問題在哪一行。
- [ ] 「用了什麼技術」列出實際用到的 kernel API 名稱。
- [ ] 「改善了什麼」是具體、可驗證的改變，並對應到第 10 節的某個驗證或板上輸出。

## C. 例子是真的

- [ ] 程式碼都由 `\snip{}` 從 repo 抽出，標題的檔名與行號和原始檔一致。
- [ ] 板上輸出是實際 log，註明日期與 bitstream 的 SHA-256 前 16 個十六進位字元。
- [ ] 說明文字裡提到的函式名、暫存器名、數字，都能在程式碼或 log 裡找到。

## D. 原理正確

- [ ] kernel 行為的描述和 Linux 6.1（`6.1.30-xilinx-v2023.2`）的原始碼一致；有疑問的地方，審稿人要實際去查 kernel source。
- [ ] 不誇大：限制要寫清楚（例如沒有 SMMU 時 DMA 沒有被完全隔離、這顆 bitstream 沒有中斷線）。
- [ ] 硬體事實（暫存器位址、位元定義、時脈、frame 時間）和 `rtl/fuse/twn_csr.v`、`results/` 一致。

## E. 面試題

- [ ] 對應的面試題在本節有答案，而且 30 秒講得完。
- [ ] 回答裡的每個名詞，前文都解釋過。

## F. 速查與排版

- [ ] 「關鍵函式速查」列出本節所有關鍵函式，並附檔案與行號。
- [ ] 程式碼沒有超出頁寬，圖表清楚，沒有殘留的「待寫」。

## G. 用語與隱私

- [ ] 用台灣繁體中文用語（記憶體、程式、介面、預設、檔案），沒有中國大陸用語。
- [ ] 沒有密碼、私人路徑、email、個人資料。
