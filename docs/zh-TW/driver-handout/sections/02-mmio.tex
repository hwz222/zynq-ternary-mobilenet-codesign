\section{MMIO：ioremap、readl／writel 與 barrier}
\label{sec:mmio}

\begin{oneline}
暫存器的實體位址 \code{0xA000_0000} 要先經 \code{ioremap} 換成 kernel 虛擬位址，之後用 kernel 提供、而且自帶順序保證（barrier）的 \code{readl}／\code{writel} 讀寫。
\end{oneline}

\begin{before}
app 把 \code{/dev/uio4} \code{mmap} 進來（第 1 章 \code{fuse_hal_init()}），得到一個 \code{volatile} 指標 \code{g_ctrl}，直接用陣列下標讀寫暫存器（第 78--79 行）。app 還得自己處理順序：先把輸入寫進 DDR、再寫 START，兩者是不同的記憶體區段，CPU 不保證先後，所以 v1.0.0 手寫了一個 barrier（第 93 行的 \code{dsb sy}）：

\snip{v100_uio_wr_rd}
\snip{v100_uio_wmb}

問題：任何能開 \code{/dev/uio4} 的程式都能寫任何暫存器；barrier 要每個寫 app 的人自己記得加，漏了，PL 可能讀到還沒寫完的輸入；kernel 也不知道這段位址被誰佔用。
\end{before}

\begin{tech}
\begin{itemize}
\item \code{devm_platform_ioremap_resource(pdev, 0)}：取出節點 \code{reg} 的第 0 段、向 kernel 登記「這段我用了」、建立映射，一次做完，driver 離開時自動解除。
\item \code{void __iomem *}：標記「這是 I/O 位址」的指標型別，靜態檢查工具 sparse 會擋下直接解指標的寫法。
\item \code{readl()}／\code{writel()}：kernel 在 \code{<linux/io.h>} 提供的 32-bit 暫存器讀寫，內含 barrier；同族還有 8、16、64-bit 的 \code{readb}／\code{readw}／\code{readq}。
\item \code{lower_32_bits()}／\code{upper_32_bits()}：把 64-bit 位址拆成兩個 32-bit 暫存器。
\end{itemize}
\end{tech}

\begin{gain}
\begin{itemize}
\item 正常使用路徑上，app 不再映射暫存器（第 4 章用 \code{/proc/<pid>/maps} 確認）；\code{/dev/mem} 這條旁路由第 10 章的 kernel 選項限制。
\item 位址範圍登記在 \code{/proc/iomem}，名字是 \code{a0000000.twn_fuse}，別的 driver 無法再登記同一段。
\item 順序保證由 \code{writel}／\code{readl} 負責，driver 裡沒有任何手寫的 barrier。
\end{itemize}
\end{gain}

\subsection{原理}

\textbf{為什麼不能直接用指標存取 \code{0xA000_0000}。}開了 MMU（把虛擬位址翻譯成實體位址的硬體）之後，程式裡的每個指標都是虛擬位址。arm64 Linux 的虛擬位址分兩半：低的一半屬於 user process，高的一半屬於 kernel。\code{0xA0000000} 當成虛擬位址落在 user 那一半，查的是當下 process 的頁表，跟實體位址 \code{0xA000_0000} 沒有關係：沒有映射就是 page fault，kernel 程式出這種錯會 oops（印出錯誤現場並終止目前的工作）；剛好有映射，則會靜默寫到某塊 user 記憶體上，更危險。kernel 自己的頁表一開始只對應 DDR，周邊的實體位址不在裡面，所以一定要先 \code{ioremap}。

\code{ioremap} 在 kernel 的頁表加一筆，屬性是 Device 記憶體；arm64 的 Linux 6.1 用 \code{PROT_DEVICE_nGnRE}。nG（non-Gathering）：不把多次存取合併；nR（non-Reordering）：對同一個裝置的存取不重排；E（Early write acknowledgement）：允許匯流排中途就回報寫完。UIO 的 \code{mmap} 給的是更嚴格的 nE。Device 記憶體也不經過 cache、不會被預先讀取，所以讀一次 done 位元就真的去硬體讀一次。

\textbf{barrier 是什麼。}程式寫的順序不等於實際發生的順序：compiler 只要單一執行緒看起來一樣就可以重排；ARM 是弱記憶體順序（weakly ordered）的架構，CPU 會亂序執行，store 先進 write buffer（CPU 送出寫入前暫放的小緩衝區），寫 DDR 和寫 PL 暫存器走不同的路徑，誰先到沒有保證。對 CPU 自己看不出差別，但 PL 是另一個觀察者。barrier 是一道「順序」指令：寫在它前面的存取，一定比後面的先被別人看到。它不搬資料、不清 cache，也不是鎖。

\textbf{\code{readl}／\code{writel} 裡面多了什麼。}Linux 6.1 的通用實作（\code{include/asm-generic/io.h}），省略追蹤與位元組順序轉換（在 little-endian 的 arm64 上不做事）：

\begin{lstlisting}[numbers=none,xleftmargin=0pt]
writel(value, addr):  __io_bw();  __raw_writel(value, addr);   /* __io_bw = dma_wmb() = dmb oshst */
readl(addr):          v = __raw_readl(addr);  __io_ar(v);      /* __io_ar = dma_rmb() = dmb oshld ... */
\end{lstlisting}

在這個 driver 裡它們各解決一個實際問題：
\begin{itemize}
\item \textbf{寫 START 之前}：app 剛把輸入影像寫進 DDR 的 buffer。\code{writel} 先做 \code{dma_wmb()}，保證這些寫入比 START 先被 PL 看到；否則 PL 可能讀到上一幀或寫到一半的影像，而且不是每次都發生，很難查。
\item \textbf{讀到 done 之後}：\code{readl} 讀完再做 \code{dma_rmb()}，保證之後讀 buffer 裡的輸出，不會被 CPU 提前到讀 done 之前，才不會讀到 PL 還沒寫完的結果。
\end{itemize}

ARM 有兩種 barrier 指令：\code{dsb}（Data Synchronization Barrier）等前面所有存取\textbf{真的完成}才往下執行；\code{dmb}（Data Memory Barrier）只保證\textbf{順序}。後綴 \code{osh}（outer shareable）指「CPU 和會存取記憶體的裝置」這個範圍，\code{st}／\code{ld} 表示只管寫或讀。v1.0.0 手寫的 \code{dsb sy} 是最重的一種；\code{writel} 的 \code{dmb oshst} 只排好寫入順序，已經足夠。\code{readl_relaxed}／\code{writel_relaxed} 則拿掉這些 barrier，用在確定不需要順序的地方。

\textbf{為什麼要「登記」位址範圍。}\code{devm_platform_ioremap_resource} 內部先呼叫 \code{request_mem_region}，在 \code{/proc/iomem} 記下這段位址屬於誰，另一個 driver 再要同一段就會失敗。它本身擋不住 \code{/dev/mem}；那要靠第 10 章的 \code{IO_STRICT_DEVMEM}，而它正是以這份登記為依據。

\subsection{面試會問}

\begin{qa}{為什麼要先 ioremap？readl／writel 跟直接解指標差在哪？}
開了 MMU 之後指標都是虛擬位址。\code{0xA0000000} 當成虛擬位址屬於 user 那一半，跟周邊的實體位址無關，kernel 的頁表裡也沒有周邊，直接存取會 page fault。\code{ioremap} 建一筆頁表，把一段 kernel 虛擬位址對到實體位址，屬性是 Device-nGnRE：不走 cache、不合併、不重排。存取一律用 kernel 的 \code{readl}／\code{writel}：它們保證每次真的讀寫到硬體，而且帶 barrier。\code{writel} 寫入前有 \code{dma_wmb}，所以 app 先寫進 DDR 的輸入一定比 START 先讓 PL 看到；\code{readl} 讀到 done 之後有 \code{dma_rmb}，之後讀輸出不會被提前。我的 driver 沒有手寫任何 barrier，全部靠這兩個函式。
\end{qa}
