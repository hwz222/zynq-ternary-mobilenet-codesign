# twn_fuse driver 開發講義（繁體中文）

這是 [`linux/driver/twn_fuse`](../../../linux/driver/twn_fuse/) 的學習講義，對象是母語為台灣華語、英文為第二語言的工程師。
目標：用最短的時間看懂每一項 Linux driver 技術，並知道程式碼裡的關鍵函式和邏輯在哪裡。

## 建置

需要 TeX Live（XeLaTeX、latexmk）與 Python 3。字型用 Windows 內建的 Microsoft JhengHei、Segoe UI、Consolas；
在其他系統上請改 `handout.tex` 開頭的字型設定。

    cd docs/zh-TW/driver-handout
    latexmk            # 先跑 extract.py 抽出程式碼，再編譯；輸出 build/handout.pdf

## 檔案

| 檔案 | 用途 |
|---|---|
| `handout.tex` | 主檔：版面、三種固定框（原本怎麼做／用了什麼技術／改善了什麼）、程式碼樣式 |
| `sections/` | 每項技術一個檔案，編號對應 driver 的工作項目 1–10；附錄 A 名詞表、B 面試六題、C 如何重現 |
| `snippets.txt` | 講義引用哪些函式（檔案＋函式名） |
| `extract.py` | 從 repo 的實際原始碼抽出整個函式並保留行號，講義裡的程式碼因此永遠和 repo 一致 |
| `REVIEW_CHECKLIST.md` | 審稿人逐項檢查的清單 |
| `REVIEW_LOG.md` | 每一輪審稿的發現與處理結果 |

## 寫作規則

每一節固定八個部分，順序不變：

1. **一句話**：讀完這一句就知道這節在講什麼。
2. **原本怎麼做**：v1.0.0 的 UIO 版本，引用 `sw/app/pl_hal_fuse.c` 的實際程式碼。
3. **用了什麼技術**：kernel API 與機制的名字。
4. **改善了什麼**：具體、可以驗證的改變，不寫空泛的好處。
5. **實際例子**：用 `\snip{}` 抽出 driver 的實際函式，逐段說明；附板上的實際輸出（log）。
6. **原理**：為什麼這樣做是對的，必要時一張圖。
7. **面試會問**：30 秒內講得完的回答。
8. **關鍵函式速查**：函式、檔案與行號、做什麼。

用語：

- 敘述用台灣繁體中文，技術名詞保留英文（probe、ioremap、mmap、ioctl、DMA、cache、mutex…），第一次出現時用一句中文解釋，並收進附錄 A。
- 不用中國大陸用語：記憶體（不是內存）、程式（不是程序）、介面（不是接口）、預設（不是默認）、檔案（不是文件）。
- 句子短，先講結論再講理由。不用沒解釋過的代號。
- 程式碼一律從 repo 抽出，不手抄；板上輸出一律貼實際 log，並註明日期與 bitstream 的 SHA-256 前 16 個十六進位字元。

## 審稿流程

寫的人不能自己審。每一節寫完後：

1. 交給審稿人（一個沒有參與撰寫的 agent），附上該節的 tex、引用到的原始碼、`REVIEW_CHECKLIST.md`。
   審稿人以目標讀者的角度讀，並對照 kernel 原始碼查證原理的敘述。
2. 審稿人的發現逐條記進 `REVIEW_LOG.md`，標明嚴重程度。
3. 寫的人修正後，審稿人再看一次，確認每一條都已處理或註明不改的理由。
4. 全部章節完成後，審稿人再對整份 PDF 做一次通讀審查，才交付。
