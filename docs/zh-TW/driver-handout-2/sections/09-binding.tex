\section{device-tree binding 與靜態檢查}
\label{sec:binding}

\begin{oneline}
v1.1 為加速器的 device tree 節點寫了一份 binding（節點的規格書 \code{wjhuang,twn-fuse.yaml}），並用它檢查 PetaLinux 實際產生的節點；kernel 官方的 \code{make dt_binding_check} 和 sparse 需要另外安裝工具，這次沒有跑。
\end{oneline}

\begin{before}[原本怎麼做（driver v1.0 與 v1.0.0）]
節點長什麼樣子沒有寫在任何地方：\code{compatible} 字串只出現在 driver 的比對表和 \code{system-user.dtsi}；節點有哪些屬性，則由 PetaLinux 從 XSA 自動產生。driver 期待的東西（例如 v1.1 一定要有中斷）和實際產生的節點之間，沒有任何東西在對照。這次就遇到一個例子：加了中斷之後，PetaLinux 除了 \code{interrupts}，還多寫了一個 \code{interrupt-names}，事先沒有人知道。
\end{before}

\begin{tech}
\begin{itemize}
\item \textbf{dt-schema 格式的 YAML}：kernel 從 2018 年左右開始改用 JSON Schema 寫 binding，放在 \code{Documentation/devicetree/bindings/}。重要的欄位：\code{properties}、\code{required}、\code{allOf} 搭配 \code{if}/\code{then}/\code{else}（依版本給不同規則）、\code{additionalProperties: false}（沒列的屬性一律不准）、\code{examples}。
\item \textbf{C 前處理器加 \code{dtc}}：範例裡的 \code{GIC_SPI}、\code{IRQ_TYPE_LEVEL_HIGH} 是 kernel 的 \code{dt-bindings} 標頭定義的巨集，要先用 \code{cpp} 展開，才能用 \code{dtc}（device tree 編譯器）編譯。
\item \textbf{\code{test/binding_check.py}}：沒有 dtschema 時能做的部分檢查。
\end{itemize}
\end{tech}

\begin{gain}
\begin{itemize}
\item 節點的規格寫成一份檔案，也寫明 v1.0 不准有中斷、v1.1 一定要有。
\item 規格和 driver 的比對表自動對照：兩邊的 \code{compatible} 字串不一致就 FAIL。
\item 對照 PetaLinux 實際產生的節點時，發現要描述 \code{interrupt-names}；補上之後，用實際的 \code{system.dtb} 檢查全部通過。
\item 誠實的限制：官方的 \code{dt_binding_check} 會用 JSON Schema 逐條驗證每個屬性的格式（例如 \code{reg} 的 cell 數），這部分沒做到。
\end{itemize}
\end{gain}

\subsection{沒有做到的兩項，以及怎麼補}

\textbf{\code{make dt_binding_check}。}這是 kernel 官方的檢查，需要 Python 套件 \code{dtschema} 與 \code{yamllint}。這次的工作環境不允許從網路安裝新套件，所以沒有跑。補的方法：

\begin{cmdline}
pip install dtschema yamllint
cp linux/driver/twn_fuse/wjhuang,twn-fuse.yaml <kernel>/Documentation/devicetree/bindings/misc/
make -C <kernel> dt_binding_check DT_SCHEMA_FILES=misc/wjhuang,twn-fuse.yaml
\end{cmdline}

另外，\code{wjhuang} 這個 vendor prefix（\code{compatible} 字串逗號前面那一段，代表廠商或作者）要正式送進 kernel，還得登記在 \code{vendor-prefixes.yaml}；這個 driver 沒有要送進 mainline（Linus Torvalds 維護的官方 kernel 原始碼樹），所以沒有做。

\textbf{sparse（\code{make C=1}）。}sparse 是 kernel 專用的靜態分析工具，最常抓到的是 \code{__user} 指標被直接取值、\code{__iomem} 指標沒經過 \code{readl()} 就使用、大小端型態混用。同樣需要另外安裝（\code{apt install sparse}，或從原始碼編譯），所以沒有跑。補的方法：

\begin{cmdline}
make -C linux/driver/twn_fuse C=1
\end{cmdline}

已經做的替代檢查是 \code{make W=1}（打開 kernel 額外的編譯器警告）與 kernel 的 \code{scripts/checkpatch.pl --strict}（程式風格檢查）。審稿時重跑發現 \code{twn_fuse_ioctl.h} 有 1 個 WARNING（檔案裡寫了自己的檔名）與 1 個 CHECK（一行超過 100 欄），修掉之後兩個檔案都是 0：

\subsection{原理}

\textbf{binding 檢查的是什麼。}device tree 是資料，不是程式：寫錯一個屬性名稱，編譯照樣成功，開機後 driver 才在 \code{probe()} 裡找不到東西。binding 把「這種節點該長什麼樣」寫成機器可以讀的規格。\code{dtc} 編譯時不看 binding，要另外跑 \code{make dtbs_check}（或本專案的 \code{binding_check.py}），才能在開機之前抓出這類錯誤。

\textbf{為什麼 \code{status}、\code{phandle}、\code{interrupt-parent} 不用寫進 binding。}這些是每個節點都可以有的通用屬性，由 dt-schema 的核心規格描述；個別的 binding 只寫自己特有的屬性。\code{binding_check.py} 把這三個列為例外，就是模仿這個規則。

\textbf{\code{if}/\code{then}/\code{else} 的作用。}同一份 binding 涵蓋兩個版本的硬體：v1.1 的節點若少了中斷，driver 會退回輪詢、照樣能用，但那是設定錯誤；v1.0 的節點若多了中斷，driver 會去等一個永遠不會來的中斷，直到 3 秒逾時。這兩種錯誤，在開機前跑 binding 檢查就能擋下。

\subsection{面試會問}

\begin{qa}{你怎麼確定 device tree 節點寫對了？}
我寫了 dt-schema 格式的 binding，列出每個屬性和必要屬性，用 \code{if}/\code{then}/\code{else} 規定 v1.1 一定要有中斷、v1.0 不准有，並設 \code{additionalProperties: false}。官方的 \code{dt_binding_check} 需要另外安裝 dtschema，這次的環境不能裝，所以我寫了一個部分檢查：binding 的 \code{compatible} 要和 driver 的比對表一致，範例要能用 kernel 的標頭和 \code{dtc} 編過，最重要的是拿 PetaLinux 實際產生的 dtb 來比對。對照時發現 PetaLinux 多產生了 \code{interrupt-names}，binding 補上後全部通過。sparse 也因為同樣的原因沒跑，我用 \code{W=1} 和 \code{checkpatch --strict} 代替，紀錄裡兩個檔案都是 0 個警告。
\end{qa}
