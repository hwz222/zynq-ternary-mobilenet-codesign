\section{限制 /dev/mem、拿掉保留區}
\label{sec:devmem}

\begin{oneline}
v1.1 的 driver 自己配 DMA buffer，所以拿掉了 v1.0.0 為 \code{/dev/mem} 保留的 256 MB，並打開 \code{STRICT_DEVMEM} 與 \code{IO_STRICT_DEVMEM}，讓 \code{/dev/mem} 不能再映射 kernel 管理的記憶體（System RAM）與 driver 佔用中的暫存器。
\end{oneline}

\begin{before}[原本怎麼做（v1.0.0）]
device tree 保留 256 MB，標成 \code{no-map}（kernel 不把它放進自己的記憶體）：
\snip{v10_dtsi_reserved}
app 用 \code{/dev/mem} 把這塊實體位址映射進來（第 1 節的 \code{uio_devmem}）。kernel 沒有限制 \code{/dev/mem}，開機組 D 的紀錄：

\boardfile{D5_boot_state.log}{26-43}

保留區佔掉 256 MB（第 27 行 \code{MemTotal} 只有 1,773,764 kB）；\code{STRICT_DEVMEM} 沒開（第 37 行）；任何 root 程式都能用 \code{devmem} 讀寫 DDR 和加速器的暫存器（第 38--43 行）。
\end{before}

\begin{tech}
\begin{itemize}
\item \textbf{拿掉 \code{reserved-memory}}：driver 的 buffer 由 DMA API 配（沒有 SMMU 時從 CMA；SMMU 打開時的情形見第 8 節），不再需要保留區。
\item \code{CONFIG_STRICT_DEVMEM}：\code{/dev/mem} 不能存取 kernel 管理的系統記憶體（System RAM，\code{/proc/iomem} 裡標成 \code{System RAM} 的範圍）。
\item \code{CONFIG_IO_STRICT_DEVMEM}：\code{/dev/mem} 也不能存取已經被 driver 佔用（busy）的 I/O 區間。
\item \textbf{kernel 設定片段}（\code{.cfg}）加 \texttt{linux-xlnx\_\%.bbappend}：在 PetaLinux 預設的 kernel 設定上，只改這幾個選項。
\end{itemize}
\end{tech}

\begin{gain}
\begin{itemize}
\item kernel 可用的記憶體多了約 255.5 MB：\code{MemTotal} 在開機組 D 是 1,773,764 kB，開機組 E 是 2,035,396 kB，多 261,632 kB。這兩次開機的 kernel 不同（v1.1 多開了 SMMU、\code{STRICT_DEVMEM} 等選項），所以這個差裡也混著兩顆 kernel 本身大小的變化，不是只差保留區。
\item \code{/dev/mem} 映射 System RAM 和加速器暫存器都被拒絕（\code{Operation not permitted}）。
\item driver 載入期間，user space 只能經過 driver 碰加速器的暫存器與 DMA buffer；第一冊做的「只給 buffer、不給暫存器」，到這一步才不能被 \code{/dev/mem} 繞過。這個保證有邊界：root 卸載 driver 後，暫存器又能用 \code{/dev/mem} 映射；不屬於 System RAM 的記憶體（DDR 最上面 1 MB）也不受限（開機組 H 實測，見下面）。
\item 代價：v1.0.0 的 UIO 版本 app 在 v1.1 映像上不能跑了，v1.1 的 app 一律用 driver（\code{HAL=drv}）。
\end{itemize}
\end{gain}

\subsection{原理}

\textbf{\code{/dev/mem} 為什麼危險。}它把整個實體位址空間開給 root：kernel 的程式碼、資料、其他 process 的記憶體、所有裝置的暫存器。任何拿到 root 的程式都能直接改 kernel，也能繞過 driver 去動硬體，driver 做的所有檢查（第一冊第 5 節的 offset 檢查）都被繞過。

\textbf{兩個選項各擋什麼。}\code{/dev/mem} 的 \code{mmap()} 對每一頁呼叫 \code{devmem_is_allowed()}（Linux 6.1 \code{lib/devmem_is_allowed.c} 第 20--27 行）：

\begin{lstlisting}[numbers=none,xleftmargin=0pt,title={\scriptsize lib/devmem\_is\_allowed.c : 20--27（Linux 6.1，節錄）}]
int devmem_is_allowed(unsigned long pfn)
{
	if (iomem_is_exclusive(PFN_PHYS(pfn)))
		return 0;
	if (!page_is_ram(pfn))
		return 1;
	return 0;
}
\end{lstlisting}

\begin{itemize}
\item \code{STRICT_DEVMEM} 讓這個函式生效。\code{page_is_ram()} 為真（屬於 System RAM）就拒絕；判斷的依據是 kernel 管理的記憶體範圍，不是「這是不是 DDR」，所以 \code{/memory} 節點以外的 DDR 不會被擋。
\item \code{IO_STRICT_DEVMEM} 影響 \code{iomem_is_exclusive()}（\code{kernel/resource.c} 第 1733--1737 行）：被 driver 用 \code{request_mem_region()} 佔用、標成 busy 的區間，也算「獨佔」。driver 的 probe 用 \code{devm_platform_ioremap_resource()}，它會先佔用 \code{reg} 範圍，所以加速器的 64 KB 暫存器也被擋下。
\item 沒有被任何 driver 佔用的 I/O 區間仍然可以用 \code{/dev/mem} 存取；driver 卸載時會釋放它佔用的區間，之後那段暫存器也一樣。
\item 要完全不給 \code{/dev/mem}，得關掉 \code{CONFIG_DEVMEM}；這個映像沒有關，所以上面兩個邊界都存在。
\end{itemize}

\textbf{為什麼以前需要保留區，現在不需要。}\code{/dev/mem} 只是把一個實體位址映射給 app，它不會配置記憶體。要讓 kernel 不去用那塊記憶體，只能在 device tree 事先保留。driver 版本改用 DMA API 配置（第一冊第 3 節），記憶體是 kernel 自己配給 driver 的（沒有 SMMU 時從 CMA 拿出一塊連續的記憶體；發佈映像打開了 SMMU，改從一般記憶體配頁，見第 8 節），kernel 知道它被誰用，不需要保留。CMA 平常沒被 DMA 用到的部分，kernel 還可以借給可搬移的一般用途。

\textbf{少掉的 512 kB。}256 MB 是 262,144 kB，\code{MemTotal} 只多了 261,632 kB。kernel 把這塊記憶體收回來時，要為它建立自己的管理結構，例如線性映射的分頁表；以 4 KB 的頁、每項 8 bytes 計算，256 MB 的分頁表剛好是 512 kB。這是推算，沒有逐項查證；而且比較的兩邊是不同開機組、不同設定的 kernel，kernel 映像本身的大小差（kernel 的程式碼與資料不算在 \code{MemTotal} 裡）也混在這個差裡，沒有拆開。

\subsection{面試會問}

\begin{qa}{為什麼要限制 /dev/mem？限制之後 app 怎麼存取硬體？}
\code{/dev/mem} 把整個實體位址空間開給 root，等於任何 root 程式都能改 kernel、繞過 driver 去動硬體。v1.0.0 需要它，因為 app 要自己映射 DMA buffer，所以 device tree 還得保留 256 MB 給它。v1.1 的 driver 用 DMA API 配 buffer，再用 \code{mmap} 只把 buffer 給 app，暫存器完全不給，所以 app 不再需要 \code{/dev/mem}，保留區也拿掉了。我打開 \code{STRICT_DEVMEM}，擋掉 kernel 管理的 System RAM；再打開 \code{IO_STRICT_DEVMEM}，擋掉被 driver 佔用的暫存器。板上用 \code{devmem} 讀這兩種位址都回 \code{Operation not permitted}，而 kernel 多了大約 255 MB 記憶體。它的邊界我也實測過：root 卸載 driver 之後暫存器又讀得到，System RAM 以外的 DDR 最上面 1 MB 也讀得到，所以這是限制，不是把 \code{/dev/mem} 關掉。
\end{qa}
