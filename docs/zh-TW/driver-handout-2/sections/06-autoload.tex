\section{開機自動載入：PetaLinux recipe}
\label{sec:autoload}

\begin{oneline}
v1.1 用 PetaLinux（Yocto）的 module recipe 把 \code{twn_fuse.ko} 編進映像、開機時自動載入，並把 device tree 節點的 \code{compatible} 改成 driver 認得的字串，開機後不再需要 driver v1.0 那些手動的 \code{insmod} 與綁定步驟。
\end{oneline}

\begin{before}[原本怎麼做（v1.0.0 的映像與 driver v1.0）]
v1.0.0 的 \code{system-user.dtsi} 把節點交給 UIO：
\snip{v10_dtsi_uio}
driver v1.0 不在映像裡。每次開機要把 \code{twn_fuse.ko} 複製到板上，再用第一冊的 \code{bind.sh} 透過 \code{driver_override} 把裝置從 UIO 搶過來。driver 也是在 PC 上對著另外複製出來的 kernel 編譯樹編的，要靠 vermagic（module 裡記錄的 kernel 版本與主要設定字串，載入時必須和執行中的 kernel 完全相同）一致才能載入。
\end{before}

\begin{tech}
\begin{itemize}
\item \textbf{Yocto module recipe}（\code{.bb} 檔）：\code{inherit module} 讓這個 recipe 依賴映像自己的 kernel，用同一棵 kernel 樹編譯 out-of-tree module（原始碼不在 kernel 原始碼樹裡、另外編譯的 module），並在 \code{do_install} 時跑 \code{modules_install}。
\item \code{SRC_URI}、\code{LIC_FILES_CHKSUM}：來源檔，以及授權宣告那一行的 md5（Yocto 要求每個 recipe 宣告授權，並用 checksum 確認它沒有被改）。
\item \code{KERNEL_MODULE_AUTOLOAD}：產生 \code{/etc/modules-load.d/twn_fuse.conf}，開機時由 systemd（這個映像的 init 系統，開機時依序啟動各項服務）的 \code{systemd-modules-load} 服務載入。
\item \code{IMAGE_INSTALL:append}：把這個套件放進 root file system。
\item \textbf{用標籤參照改寫節點}：\code{system-user.dtsi} 裡的 \texttt{\&fuse\_0 \{...\}} 參照 PetaLinux 產生的節點的標籤，編譯 device tree 時覆寫它的 \code{compatible}。這是建置時的覆寫，不是執行期才套上的 device tree overlay（\code{.dtbo}）。
\end{itemize}
\end{tech}

\begin{gain}
\begin{itemize}
\item 開機到可以用不需要任何手動步驟：開機第 4.8 秒 driver 就載入並綁上（開機組 E 的 dmesg）。
\item driver 與映像的 kernel 一定相符：module 和 kernel 在同一次 PetaLinux 建置裡用同一棵樹編出來。
\item repo 裡只有一份 driver 原始碼：\code{build_linux.sh} 建置時把它複製進 recipe。
\item UIO 不再碰這個裝置：節點的 \code{compatible} 不再是 \code{generic-uio}。
\end{itemize}
\end{gain}

\subsection{原理}

\textbf{開機時 module 是怎麼被載入的。}有兩條路，這個映像兩條都有：
\begin{itemize}
\item \textbf{依 modalias}：kernel 建立平台裝置時送出 uevent，帶著 \code{MODALIAS}（內容是 \code{of:N...T...C} 加上節點的 \code{compatible}）；udev 用內建的 libkmod 載入它（效果等同執行 \code{modprobe}），也就是在 \code{modules.alias} 找到這個字串屬於 \code{twn_fuse}（來自第一冊講過的 \code{MODULE_DEVICE_TABLE(of, ...)}）。
\item \textbf{依清單}：\code{systemd-modules-load} 讀 \code{/etc/modules-load.d/*.conf}，逐一載入。
\end{itemize}
不論哪一條先載入，第二條都只會發現它已經載入。載入後，driver core 用 \code{compatible} 比對（第一冊第 1 節），呼叫 \code{probe()}。

\textbf{為什麼不用手動 \code{insmod} 了，也不需要 \code{driver_override}。}\code{driver_override} 是在 \code{compatible} 對不上時強迫綁定的手段。節點的 \code{compatible} 已經是 driver 認得的字串，正常的比對就會成功。\code{bind.sh} 仍然保留：要測模組參數（例如 \code{use_irq=0}）時，用它卸載後帶參數重新載入。

\textbf{\code{inherit module} 做了什麼。}它讓 recipe 依賴 \code{virtual/kernel}，在編譯時把 \code{KERNEL_SRC} 指向這次建置的 kernel 樹，安裝時把 \code{.ko} 放進 \code{/lib/modules/<版本>/extra/}，並在映像建立時跑 \code{depmod}：它掃描所有 module，產生 \code{modules.alias} 這張「裝置的 modalias 字串 → module 名稱」的對照表。第一冊在 PC 上自己準備 kernel 樹、自己對 vermagic，這些現在都交給建置系統。

\subsection{面試會問}

\begin{qa}{driver 怎麼做到開機就自動載入？}
我寫了一個 Yocto 的 module recipe：\code{inherit module} 讓它用映像自己的 kernel 樹編譯，所以 vermagic 一定對；\code{KERNEL_MODULE_AUTOLOAD} 產生 \code{/etc/modules-load.d} 的設定，開機由 systemd 載入；\code{IMAGE_INSTALL} 把它放進 rootfs。device tree 在 \code{system-user.dtsi} 把 PetaLinux 產生的節點的 \code{compatible} 改成 driver 比對表裡的字串，所以載入後 driver core 直接比對成功、呼叫 probe，不再需要 \code{driver_override}。另外 udev 也會用 modalias 載入它，兩條路都在。板上開機第 4.8 秒 driver 就綁好，用中斷模式。
\end{qa}
